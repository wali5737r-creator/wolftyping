# Typing Master — Foundation

Windows-first desktop typing trainer (English + Urdu). Flutter + GetX + Drift/SQLite.

This is the **foundation only** (per the agreed scope): folder structure, GetX
setup, theme, routing, database schema, basic desktop shell + sidebar, and the
app entry point. No typing engine, no lessons content, no fake stats yet.

## One-time machine setup

This project's `windows/` platform folder is **not included** — it must be
generated by your local Flutter SDK (it contains generated C++ runner files
that don't belong in hand-written source). From the project root:

```bash
flutter pub get
flutter config --enable-windows-desktop
flutter create --platforms=windows .
dart run build_runner build --delete-conflicting-outputs
flutter run -d windows
```

The last command (`build_runner`) generates `lib/core/database/app_database.g.dart`
from the Drift table definitions — the app will not compile without it.
Re-run it any time a table in `lib/core/database/tables/` changes.

## Design decisions worth knowing

- **Sidebar stays persistent across navigation** by having every page wrap
  its body in `AppScaffold(currentRoute: ..., body: ...)`. Clicking a sidebar
  item calls `Get.offNamed(route)` (not `toNamed`) so the desktop app doesn't
  build up a deep back-stack the way a mobile app would.
- **`AppSidebar` takes `currentRoute` as an explicit parameter** rather than
  reading `Get.currentRoute` reactively — that getter isn't observable, so
  relying on it inside `Obx` would silently never rebuild.
- **`Users`/`Settings`/`Streaks` are modeled as tables**, not hardcoded to a
  single row, so multi-profile support won't require a schema rewrite later,
  even though v1 only ever creates one user.
- **No `windows/` folder, no `*.g.dart` files** are included — both are
  machine-generated (see setup steps above) and shouldn't be hand-authored
  or reviewed as source.
- Nothing here calculates WPM/accuracy or stores a test result — that's the
  Typing Engine, built next, exactly as scoped.
